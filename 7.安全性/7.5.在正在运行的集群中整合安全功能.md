您可以通过前面讨论的一种或多种受支持的协议来保护运行中的集群。这是分阶段完成的:

· 逐步反弹集群节点以打开其他安全端口。

· 使用安全端口而不是PLAINTEXT端口重新启动客户端（假设您正在保护客户端broker连接）。

· 再次递增反弹集群以启用broker到broker的安全性（如果需要）

· 最后一次增量反弹以关闭PLAINTEXT端口。

在[7.2](#security_ssl)和[7.3](#security_sasl)节中介绍了配置SSL和SASL的具体步骤。请按照以下步骤为所需的协议启用安全性。

通过安全性实施，您可以为broker-客户端和broker-broker通信配置不同的协议。必须在单独的跳动中启用这些功能。PLAINTEXT端口必须始终保持打开状态，以便broker和/或客户端可以继续进行通信。

进行增量反弹时，请通过SIGTERM彻底停止broker。在移至下一个节点之前，等待重新启动的副本返回ISR列表也是一种好习惯。

例如，假设我们希望使用SSL加密broker-客户和broker-broker通信。在第一个增量跳动中，在每个节点上打开一个SSL端口:

listeners = PLAINTEXT:// broker1:9091，SSL:// broker1:9092

然后，我们重新启动客户端，将其配置更改为指向新打开的安全端口:

bootstrap.servers = [broker1:9092，...]

security.protocol = SSL

...等等

在第二次增量服务器退回中，我们指示Kafka使用SSL作为brokerbroker协议（它将使用相同的SSL端口）:

listeners = PLAINTEXT:// broker1:9091，SSL:// broker1:9092

security.inter.broker.protocol = SSL

在最后一次反弹中，我们通过关闭PLAINTEXT端口来保护集群:

listeners = SSL:// broker1:9092

security.inter.broker.protocol = SSL

或者，我们可能选择打开多个端口，以便可以将不同的协议用于broker-broker和broker-客户通信。假设我们希望在整个过程中使用SSL加密（即，用于broker-broker和broker-客户通信），但我们也想向broker-客户连接添加SASL身份验证。我们可以通过在第一次反弹期间打开两个其他端口来实现此目的:

listeners = PLAINTEXT:// broker1:9091，SSL:// broker1:9092，SASL_SSL:// broker1:9093

然后，我们将重新启动客户端，更改其配置以指向新打开的SASL和SSL安全端口:

bootstrap.servers = [broker1:9093，...]

security.protocol = SASL_SSL

...等等

第二台服务器反弹将通过我们先前在端口9092上打开的SSL端口将集群切换为使用加密的broker-broker通信:

listeners = PLAINTEXT:// broker1:9091，SSL:// broker1:9092，SASL_SSL:// broker1:9093

security.inter.broker.protocol = SSL

最后的反弹通过关闭PLAINTEXT端口来保护集群。

listeners = SSL://broker1:9092，SASL_SSL://broker1:9093

security.inter.broker.protocol = SSL

ZooKeeper可以独立于Kafka集群进行安全保护。[7.6.2](#zk_authz_migration)节介绍了执行此操作的步骤。
